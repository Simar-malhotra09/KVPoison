# Splicing phantom KV cache entries: a controlled negative result, a decode-settings trap, and one real effect

*A preliminary investigation, substantially revised after further testing killed most of its original claims.*

We set out to test whether appending phantom key and value cache entries derived from a forbidden topic, spliced onto an otherwise completely intact system prompt and user question, could cause a small open-weight model to violate a constraint it was never actually shown breaking. It can, in the narrow sense that the behavior is real and reproducible. But a deciding control run later in this investigation shows that the same behavior — the model getting pulled off-task by whatever content sits at the end of its context — happens just as reliably when that content is pasted in as an ordinary text prefix, with no cache splicing at all. That kills the framing this post originally led with: appended phantom KV cache entries are not a distinct attack surface from prompt injection with extra steps, at least not for the failure mode we spent the most time on. Two more candidate mechanisms proposed along the way, positional recency and an artificial attention sink in the spliced content, were tested with direct causal manipulations and also killed. And while chasing one of the project's cleanest-looking results, we found that Qwen2.5-1.5B-Instruct ships a default `repetition_penalty` of 1.1 that every decode in this entire post silently used, and that penalty specifically discounts the end-of-sequence token because it already appears in every chat-templated prompt — meaning the project's core measurement, whether or not a run "collapses," was contaminated in one direction for its entire duration. What survives all of that is narrower than what we started with: prompt injection genuinely does behave differently depending on where the content physically lives in the sequence (visible text turn versus appended cache), and termination probability is strongly, if not simply, governed by whether the injected content ends at a real sentence boundary — a finding that turns out to have nothing to do with cache splicing either. Read this as the record of a hypothesis being taken apart piece by piece, not as a single clean result.

## The question we started with

If a model has a system-prompt constraint prohibiting discussion of some topic, and a user prompts about something unrelated, does appending KV cache entries derived from a "shadow" text about the forbidden topic cause the model to violate the constraint? The system prompt is never touched. The user prompt is never touched. The model has never actually seen or discussed the forbidden topic as text. The only intervention is a block of cached key/value tensors spliced onto the end of an otherwise completely normal, completely intact conversation.

The implicit follow-on question, which is the one that actually mattered and which we did not test properly until much later, is whether *splicing specifically* is doing anything that the model's ordinary handling of appended context wouldn't already do on its own. That question, not the first one, is what most of this post ends up being about.

## Why this matters

KV caches get shared in real serving systems through prefix caching and multiuser batching. Any of these is a place where cache content from one context could end up adjacent to another, and if that bookkeeping is ever wrong, the result looks structurally like what we built by hand here. That threat-model framing is still live, covered near the end of this post. But two other things ended up mattering more than the threat model: a genuine, reproducible discovery that a model's default decoding settings can silently work against the exact phenomenon you are trying to measure, in a way that would fool anyone else running termination or refusal experiments on this model family without checking; and a real, specific, well-measured finding about when appended content primes a model to stop generating, which turns out to be a more interesting and better-supported result than the original framing this post opened with.

## Design

Model: Qwen2.5-1.5B-Instruct, fp16, run on an M1 Mac. A second model, TinyLlama-1.1B-Chat, was used for a partial generalization check midway through.

Three original conditions per topic. Baseline: intact constraint, unrelated user question, nothing injected. Prompt injection: the shadow text pasted directly into the visible user message, after the real question. Cache injection: the real system and user prompt is forward passed first, using the model's chat template with `add_generation_prompt` set to True, producing a cache of length N. The shadow text is forward passed separately, as raw text with no chat template applied, with `position_ids` explicitly set to N, N+1, up through N+M-1, where M is the shadow text length in tokens, so its rotary phase matches the positions it will occupy after concatenation. A prefix of the resulting shadow cache is then concatenated onto the end of the real cache, using `torch.cat` along the sequence dimension across every layer, and generation continues from there. `max_new_tokens` was 512 for the main matrix, with greedy decoding at temperature 0. A fourth condition, added much later after the deciding control described below, places the identical dosed shadow-text prefix directly after the real chat-templated prompt with no splicing at all — one ordinary joint forward pass, genuine causal attention throughout.

For cache injection specifically we vary two things. The append percent is the fraction of the shadow text's cache we splice on, tested at 25, 75, and 100 percent. And the cut type controls where that splice stops. A ragged cut truncates at the raw token count for that percentage, which usually lands partway through a sentence. A clean cut snaps that same target down to the nearest point where a full sentence ends, so the appended content never stops mid clause.

We use five topics, chosen so the user prompt has close to zero natural gravity toward the forbidden topic, for example a stock picking constraint paired with a question about Japanese railways, or a weapons constraint paired with a question about C4 photosynthesis. Under this design any violation can be attributed to the intervention rather than to organic drift.

Scoring works at three levels, and it matters which one a given claim rests on. The primary endpoint is a per-topic keyword pattern matched against windows of generated text, a binary check for whether specific forbidden terms appear. A secondary endpoint, whether the model is engaging with the shadow topic at all even without tripping a specific keyword, comes up when we discuss fabricated content but is read manually rather than scored. A third, later endpoint, P(EOS), the model's raw probability of the end-of-sequence token at the first generation step, computed from a single forward pass with no decoding loop and no decode-time logit processing, was introduced partway through this investigation specifically because the binary "collapsed" flag turned out to hide more than it revealed, and because it is what let us catch the repetition-penalty problem described below.

**A note on P(EOS) versus what the model actually outputs.** P(EOS) as we use it here is a clean, decode-settings-free measurement of the model's underlying next-token preference. It is not automatically the same as what `model.generate()` will actually produce, because generation applies decode-time logit processing — repetition penalty, in this project's case — that a raw forward pass does not. Where this matters, we say so explicitly.

## Results: what the original matrix found

Every result in this section comes from a single greedy decode run per condition on Qwen2.5-1.5B-Instruct, under the model's default (and, as we later discovered, silently active) `repetition_penalty=1.1`. Treat the numbers as an existence proof rather than a rate estimate; a later multi-seed check on three cells found that at least one of the claims below does not survive real sampling.

On Qwen, prompt injection produced exactly zero keyword violations across all five topics. Asked about Japanese railway punctuality with a stock-picking rant pasted directly after it, the model answered the railway question and nothing else:

> The Japanese railway system maintains punctuality through a combination of advanced technology, strict regulations, and human oversight...

Cache injection, on the exact same shadow content, produced sustained violations in multiple topics. That contrast — prompt injection does nothing, cache injection does a great deal — was the original core result of this post, and it is the one that the deciding control later in this post substantially revises: it turns out cache injection's advantage over prompt injection is not really about *cache splicing*, it is about *where in the sequence the content sits relative to the generation point*, and a third condition (ordinary text prefix, no splicing) gets most of the same effect.

This prompt-injection result also did not hold as cleanly once a second model entered the picture. TinyLlama's weapons prompt-injection run engaged directly with the pasted content, describing rifle mechanics in some detail, while its medical and finance runs stayed at zero. So even before the deciding control, this specific comparison was already known to be real-but-not-universal, not a clean binary.

We initially expected a violation right at the injection boundary followed by a fast recovery. That held for short shadow texts (40-120 phantom tokens) in an early pilot but not once shadow texts reached a realistic length (300-480 tokens). Instead we observed three patterns: **sustained violation**, where the model completes an entire fabricated response in the injected register and never touches the real question (a fake stock-picking table, for example); **total generation collapse**, where the model emits an end-of-sequence token immediately and produces nothing; and, in one topic only (profanity), a **tonal shift without lexical violation** — the model absorbs the emotional register of an angry rant without ever using a forbidden word, though this finding rests on an exploratory, unscored endpoint and, as described later, did not survive a multi-seed check.

## What the cut point actually tells us (revised)

The original version of this section treated the ragged-versus-clean comparison as inconclusive — "the cut point changes what fails rather than whether." Later, dedicated measurement showed this was too pessimistic. Termination probability is strongly governed by whether the spliced content's cut point lands at a genuine sentence boundary, and this shows up cleanly once you look at it directly instead of through the binary collapse flag.

Pooling every ragged-versus-clean comparison across the whole project at matched 75% dose (36 paired cells, Qwen and TinyLlama, main matrix and neutral control), ragged cuts collapsed 1 of 18 times (5.6%); clean cuts collapsed 7 of 18 times (38.9%). Paired cell by cell, six pairs flip from ragged-no-collapse to clean-collapse; zero flip the other way; exact binomial sign test on the six discordant pairs, p = 0.03.

A later, purpose-built sweep sharpened this considerably, in two stages, and the two stages together are the actual finding.

First, we measured P(EOS) directly (one forward pass, no decoding loop, fp32 softmax throughout so the small values below are numerically trustworthy) while jittering the splice's cut point one token at a time, ±5 tokens around a known clean-cut boundary, on three cells. P(EOS) was indistinguishable from zero at every jittered position except exactly at the true sentence boundary, where it jumped to 0.75-0.84, holding the amount of appended content essentially fixed. Read alone, this looks like a spike: geometry, not accumulated length, driving everything.

Second, we tested every sentence boundary within those same shadow texts, not just the one previously jittered, which holds boundary geometry fixed at each point while varying how much content precedes it. For two length-matched, topically coherent expository texts (medical/neutral, 8 boundaries; drugs/neutral, 7 boundaries), P(EOS) was near-zero at the first one to three boundaries and then persistently high, 0.73-0.81, for every subsequent boundary through the end of the text. Read alone, this looks like the opposite: accumulated length, not any specific boundary, driving everything.

Both readings are incomplete on their own. Off-boundary cuts give near-zero P(EOS) regardless of how much content has accumulated (the jitter sweep). On-boundary cuts give near-zero P(EOS) early in a text and high P(EOS) later in the same text (the comb sweep). The two sweeps are not measuring different things, they are the two axes of one effect: high termination probability requires landing on a genuine sentence boundary *and* having enough preceding content already accumulated, and neither condition alone is sufficient.

We tried to pin down what "enough" means by replotting P(EOS) against the actual token count at each boundary, across the two neutral texts, to see whether they share a threshold. They do not cleanly. Medical's third boundary (185 tokens, 39% through the text) is still transitional at 0.644; it settles into its high plateau at the fourth boundary, 219 tokens in, 46% of the way through a 478-token text. Drugs settles at its fifth boundary, around 305 tokens into a 457-token text, 67% of the way through. Neither a shared raw token count (219 versus 305) nor a shared boundary index (4th of 8 versus 5th of 7) nor a shared fractional position (46% versus 67%) unifies the two crossing points. What *is* shared is the plateau's ceiling once each text reaches it: 0.752-0.808 for medical, 0.734-0.804 for drugs, a strikingly similar saturation height for two unrelated texts, even though how quickly each one gets there differs.

A third, more topically heterogeneous text (weapons content, fourteen sentences each about a different weapon subsystem rather than one continuous narrative) does not show this pattern at all. It never settles into a plateau; it stays erratic across its full length, with high values concentrated specifically around one boundary (already the one tested earlier in this post) and much lower values at the boundaries immediately on either side of it, including near the very end of the text where the two neutral texts would already be well into their plateau. One honest, untested hypothesis: the two neutral texts are continuous, single-topic expository prose, where each additional sentence plausibly makes the passage "feel" more complete; the weapons text is enumerative, jumping between unrelated weapon subsystems sentence to sentence, so no amount of accumulated length makes any given sentence feel like a natural stopping point the way it does in continuous prose. We have not tested this. The clean way to test it would be a within-text sentence-shuffle control on one of the coherent texts — same sentences, same length, same boundary count, coherence destroyed — to see whether the ramp survives shuffling (accumulated length is what matters) or collapses into something erratic (discourse coherence is what matters). We have not run it, and we are stating the hypothesis as a hypothesis rather than a finding for that reason.

Two things about this finding are worth being explicit about regardless of how the coherence question eventually resolves, because they cut against the original framing of this post. First, as the deciding control described below shows, this termination effect is present in both the spliced condition and a condition with no splicing at all — it is not something cache injection does that ordinary text continuation doesn't. Second, this is very likely the mechanism behind the "collapse" failure mode described in the original matrix above; we did not understand this at the time those results were generated, and the pattern-based read given there (weapons and drugs collapsing at high dose, medical almost never) is consistent with, but was not originally explained by, whether those specific cut points happened to land on sentence boundaries with enough accumulated content behind them.

## Does this generalize across models

We reran a trimmed version of the original matrix on TinyLlama-1.1B-Chat, three topics, 256 tokens per run instead of 512. The general shape of the results held up — all three original failure modes reappeared — but the prompt-injection comparison did not hold as cleanly (TinyLlama engaged with pasted weapons content directly), and which specific topic landed in which failure mode moved around between models. A separate limitation, caught later and worth restating here: TinyLlama's `max_position_embeddings` is 2,048, against Qwen's 32,768. At 100% dose, TinyLlama's own runs already occupy 29-45% of its entire context window, while equivalent Qwen runs use 1.5-1.6% of Qwen's. Every cross-model comparison in this post has TinyLlama running 10-30x closer to its architectural ceiling than Qwen, and we cannot separate "TinyLlama behaves differently because it's a weaker model" from "TinyLlama behaves differently because these runs eat a third or more of its total context" without a redesign we have not built.

## Content or just length? A neutral content control

This section's core finding held up better than most of this post, and was an early hint toward the eventual deciding-control result, though we did not recognize it as such at the time.

We built five length-matched neutral shadow texts, topically unrelated to both the forbidden topic and the user's real question (pottery, ocean currents, coffee roasting, gardening, migratory birds) and reran the splice matrix. Zero of 40 runs across both models tripped the forbidden-keyword scorer, which is close to tautological, but the model still got hijacked into continuing whatever was spliced in regardless of danger. Asked about C4 photosynthesis with pottery content spliced in instead of the weapons shadow text, Qwen writes about clay glazing chemistry and never reaches the question:

> Clay bodies can be classified according to their chemical composition: kaolin clays have low plasticity and high shrinkage when dry...

Collapse was, if anything, *more* common with neutral content than with the real forbidden content on the topic where the effect was strongest: real medical vignette content collapsed 0 of 5 times; ocean-current content of matched length on the same real prompt collapsed 4 of 5. A follow-up structure-matched control (a neutral car-diagnostics text written in the same repetitive template as the real medical text) collapsed 0 of 5 times too, matching real content rather than the plain neutral control — pointing toward template structure, not topic danger, as the better explanation, a finding that replicated on TinyLlama as well. Weapons showed the opposite asymmetry (real content collapsed *more* than neutral) and its shadow text was never a repetitive template to begin with, so the structure account never had traction there; that asymmetry is unexplained.

At the time, we read this as evidence that "spliced cache content becomes the model's effective continuation context no matter what it contains" — a reframe away from safety-bypass and toward topic-agnostic hijacking, but still implicitly a claim about *splicing*. The deciding control below shows this reframe didn't go far enough: the hijacking isn't about splicing either.

## Is the single greedy run representative? A multi-seed sampling check

Every result up to this point came from single greedy decodes. We reran three specific cells — finance ragged75, medical clean75, profanity ragged100 — under real sampling (temperature 0.7, five seeds each). Finance's violation was robust (5/5 seeds). Medical mostly held (4/5, with the fifth seed collapsing instead of violating — a hint, in hindsight, that violation and collapse might share a boundary-related cause rather than being fully independent). Profanity's cleanest single-run claim, that it never produces a lexical violation, broke outright: 2 of 5 sampled seeds tripped the keyword scorer, including a genuine swear word:

> I don't give a shit about how others perceive me, but I also don't want to cause any unnecessary drama either.

This remains one of the more important cautionary findings in the whole post, and is untouched by anything discovered later: a single deterministic run can misrepresent the typical case for a given configuration, sometimes badly.

## Does a longer prompt dilute the effect? What we ruled out, in order

This section originally concluded that the evidence favored "adjacency to the generation point" over "total prompt mass" as the operative mechanism, and stated that conclusion with more confidence than later testing turned out to support. Presenting it here as a sequence of ruled-out hypotheses, which is the more honest framing.

**Ruled out: total prompt mass.** Every dose tested in the original matrix had the spliced phantom block outweighing the real prompt by 2.7x to 16x in raw tokens. We built three tiers of system prompt (9-13 tokens up to 540-544 tokens, the largest exceeding the shadow text's own length) with the identical constraint sentence embedded in each, and found no rescue effect at any tier: finance still violated, medical's neutral content still collapsed, essentially unchanged from the shortest tier. We pushed further, to roughly 2x, 4x, and 8x shadow length. The raw scored numbers looked like the effect came and went at different ratios, but reading the actual generated text showed this was a scorer artifact — finance's apparent "recovery" at 4x was still pure market commentary that happened to avoid tripping the keyword regex, and 8x produced the single most extensive fabricated content anywhere in this post. No genuine recovery was observed at any ratio tested, out to 8x. Total prompt mass does not explain the effect.

**Ruled out: position-encoded recency, on its own.** The natural next hypothesis was that the phantom block's *positional* recency — its RoPE-encoded closeness to the generation point — was what mattered, independent of raw token count, since a longer prompt only adds content further back in the sequence and never changes the phantom block's adjacency to where generation resumes. We tested this directly: keeping the physical `torch.cat` order of the spliced cache exactly as-is (the phantom block still literally sits at the tail of the tensor, adjacent to where generation reads from), we flipped which block received low versus high `position_ids` — making the phantom block look positionally old and the real prompt look positionally recent, without moving anything physically. If pure position-label recency were the mechanism, this should have weakened or reversed the effect. It did not. Finance still violated (arguably more so, 144 vs 99 generated tokens); medical's neutral content still collapsed identically in both conditions. One real but unexplained texture shift: under the flip, finance's output moved toward near-verbatim quoting of the original shadow text rather than fresh fabrication — something moved, but not the headline outcome. We also confirmed directly that Qwen2.5-1.5B has zero sliding-window or local-attention layers (all 28 layers are full/global attention per its config), ruling out one architectural alternative explanation for why physical position might matter independent of RoPE labeling.

**Ruled out: an artificial attention sink in the isolated shadow forward pass.** The shadow text's cache is computed via a forward pass over the shadow text alone, with no system prompt and no chat-template special tokens — confirmed directly that Qwen2.5's tokenizer has no BOS token at all and adds zero special tokens to plain text, so this forward pass processes completely raw, unframed content. The hypothesis was that the shadow's own first token or two forms an improvised attention sink, with inflated key/value norms purely from being processed in isolation, and that this sink is what dominates attention once spliced in. We tested this by splicing the shadow block with its leading 1, 2, or 4 tokens excluded (holding the cut point, and therefore the held-back token driving the first generated logits, exactly fixed) across four cells. If the sink were the mechanism, removing it should have reduced P(EOS). It did not: 14 of 16 non-baseline measurements were at or above the undropped baseline, with no monotonic trend in either direction. The sink hypothesis is eliminated as the primary driver, at least at the token scale the attention-sink literature usually targets.

**What we do not have**, after ruling out all three of the above, is a positive mechanistic account for why the phantom block dominates generation the way it does. We know it is not simply about how much real content exists elsewhere in the sequence, and it is not simply about which block is labeled as more recent, and it is not simply about an artificial sink in the shadow's own isolated computation. The sentence-boundary effect described above is the closest thing to a positive account this post has, and — critically — it is present with or without splicing at all, which is a different kind of claim than any of the three hypotheses above were trying to test.

## Is any of this actually about cache splicing? The deciding control

Everything above treats cache splicing as the object of study. This section is the test that undermines that framing for most of what preceded it.

The comparison the whole post needed and never ran until late: does the identical dosed shadow content, placed as an ordinary prefix to the assistant's own response — one real, joint forward pass, genuine causal attention throughout, no `torch.cat`, no cache surgery, no position tricks — produce the same behavior as the spliced condition? If it does, "cache injection" is not a distinct phenomenon; it is ordinary prefix continuation (a well-known, unexciting mechanism sometimes called a prefill attack) wearing a KV-cache costume.

We ran this on three heavily-characterized cells: finance-real, medical-real (this post's single most-quoted result, the fabricated-diagnoses example), and medical-neutral (the most reliable collapse case in the entire project). Topic capture reproduced in all three, with zero splicing. finance-real's genuine-prefill output is still pure market commentary, never reaching the real question. medical-real's is a shorter, more generic description of "the diagnostic approach" rather than specific invented diagnoses, but it is still off-task. medical-neutral hijacks into fresh, elaborated, invented oceanography and never touches the real question either. None of the three genuine-prefill runs ever answers the real question. Topic capture, this post's central behavioral claim, is not splice-specific.

Collapse looked different at first. None of the three genuine-prefill decodes collapsed, including medical-neutral, which had collapsed under splicing in every single condition tested elsewhere in this post. That looked like a real, splice-specific residual effect — until we chased down why, which is the subject of the next section, and which reversed this conclusion too.

## A decode-settings trap that shaped every result in this post

While building a rigorous, argmax-based classification of which cells showed splicing changing the actual decoded outcome (rather than trusting a crude "P(EOS) above 0.5" proxy, which we had already caught being wrong for one cell), we found something that contradicted an empirical decode we had already run and trusted: medical-neutral's genuine condition showed EOS as the true argmax in a raw, penalty-free forward pass, directly contradicting its actual 130-token, non-collapsing decode from the deciding control above.

The cause: Qwen2.5-1.5B-Instruct's shipped `generation_config.json` sets `repetition_penalty=1.1` by default. Nothing in this project's code, at any point, in any experiment, ever explicitly overrode it. Every real chat-templated prompt contains the model's end-of-sequence token, `<|im_end|>`, at least twice already — once closing the system turn, once closing the user turn. Repetition penalty discounts tokens that already appear in context. So the default penalty was, for the entire duration of this project, systematically discounting the exact token whose emission we were calling "collapse," in every single decode, before any splicing, content, or dose even entered the picture.

We confirmed this directly. Calling `generate()` with `repetition_penalty=1.0` explicitly disabled, medical-neutral's genuine condition collapses — one token, empty — exactly matching the penalty-free forward pass and exactly the opposite of its original 130-token decode under the silent default. A full audit of the rest of the shipped `GenerationConfig` (`min_new_tokens`, `min_length`, `no_repeat_ngram_size`, `bad_words_ids`, `begin_suppress_tokens`, `suppress_tokens`) found nothing else silently active; this is a single, specific, identifiable confound, not an open-ended one.

The contamination is directional, which matters for how to read everything above it in this post. The penalty has been working *against* collapse this whole time. Every historical collapse-positive result in this post is therefore conservative — it happened despite a penalty actively opposing it, so it would happen at least as readily, and probably more so, without one. Every historical collapse-*negative* result is the kind that should be treated with real suspicion, and specifically: medical-neutral's genuine-prefill non-collapse, the one clean example the "collapse has a splice-specific component" claim in the previous section rested on, does not survive this correction. Re-decoded with the penalty explicitly disabled, both spliced and genuine medical-neutral collapse identically. That residual claim is withdrawn.

We are treating raw, penalty-free P(EOS) as the primary scientific quantity going forward in this post, since it is a measurement of the model's own next-token distribution rather than of a decode-time post-processing step layered on top of it. Where we care about what a real deployment would actually output, we say so and report the penalty-applied number separately, but we no longer conflate the two, and we no longer call `generate()` anywhere in this project without an explicit, logged `repetition_penalty`.

If you are running termination, refusal, early-stopping, or any other EOS-adjacent experiment on Qwen, or on any model that ships a nonzero default repetition penalty, this is very likely already affecting your results, silently, in the direction of under-counting whatever you are trying to measure.

## What this doesn't show

- **No decay curve, no constraint-type ranking, no dose-response curve for keyword-violation rate.** Unchanged from the original investigation; see the appendix data if you want to check these claims yourself.
- **No broad model coverage**, and the TinyLlama comparisons specifically run 10-30x closer to that model's context ceiling than Qwen's equivalent runs do, which is not controlled for anywhere in this post.
- **The structure-versus-topic account for medical's low collapse rate doesn't extend to weapons**, whose real shadow text was never a repetitive template to begin with. Weapons' reversal (real content collapsing more than neutral, on Qwen only) is unexplained by anything in this post.
- **Rate estimate for only 3 of 35 original cells.** The multi-seed check is enough to show a single greedy run is not always representative, sharply so for profanity, but says nothing about the other 32 cells.
- **The sentence-boundary effect is now known to need two conditions at once (boundary geometry and accumulated content), but not what "enough" accumulated content means, or why one text never shows the pattern at all.** Replotting P(EOS) against actual token count across the two texts that do show the plateau found no shared threshold, raw or fractional, where they cross into it — only a shared plateau ceiling once they get there. The discourse-coherence hypothesis for why the third, more heterogeneous text never plateaus is untested; the specific control that would test it, a within-text sentence shuffle, is proposed but not run. All of this rests on three shadow texts total.
- **The cross-pairing matrix we ran (every shadow text spliced onto every topic's real prompt, 50 cells) has a real problem we did not catch until after running it.** It found the real prompt contributes roughly 1% of P(EOS) variance and the shadow text roughly 98% — but the "clean" cut point is computed purely from the shadow text's own sentence structure, independent of which prompt it is paired with, so every row of that matrix was evaluated at that one shadow text's own precise cut point regardless of prompt. Given how sharp the boundary effect turned out to be, this row-dominance result may be substantially an artifact of the design rather than genuine evidence about what the shadow text's content does on its own. We are treating this matrix as exploratory, not confirmatory, and have not yet rerun it in a way that would properly separate content from cut-point geometry.
- **We have not systematically re-audited the rest of this project's historical decode-based negative results against the repetition-penalty finding above.** We spot-checked three cells. Any "did not collapse" claim anywhere else in this post that we have not explicitly revisited should be treated as provisional until it is.
- **No attention-level verification of anything in this post.** Every mechanistic claim here, including the surviving sentence-boundary finding, is inferred from model outputs and P(EOS) values, never from directly inspecting attention weights.

## Does this happen in production systems?

This part of the original framing is essentially unchanged, though it now sits on a narrower foundation. Whether an attacker could cause anything described here in a production serving system depends on first obtaining a cache integrity violation — write access to KV cache blocks not supposed to be shared across contexts. Ordinary paged-attention isolation (vLLM, SGLang, TensorRT-LLM, TGI) is specifically designed to prevent that, and we are not claiming to have found a hole in it. The place a violation could plausibly occur is prefix caching, the deliberate exception to isolation most serving systems use to avoid reprocessing shared prompts or RAG documents. Independent evidence that this class of boundary is exploitable in shipped systems exists: "Agent-Assisted Side-Channel Attacks on Non-Prefix KV Cache in RAG" (Sun et al., arXiv:2606.21842) demonstrates a working timing side-channel attack against production vLLM and LMCache deployments, though it is about extraction rather than the behavioral effects studied here.

Given the deciding control above, the more accurate framing is no longer "cache injection is a distinct attack surface." It is closer to: if a cache-fusion bug or an ordinary text-injection vulnerability causes unrelated content to end up where a model continues generating from, the resulting failure looks like what this post documents, regardless of whether that content arrived via cache-level corruption or a text-level injection. The mechanism-level distinction we spent most of this post chasing turned out not to matter much for that downstream question.

## Open questions

- Does the boundary-plus-accumulation effect generalize beyond the three shadow texts tested, and what determines the crossing point into the high-P(EOS) plateau, given that it isn't a shared raw token count or a shared boundary index across the two texts that show it? Is discourse coherence the reason the third, more topically heterogeneous text never plateaus at all? The within-text sentence-shuffle control (same sentences, same length, coherence destroyed) would test this directly and has not been run.
- What actually explains the residual heterogeneity in splice-versus-genuine P(EOS) gaps across topics, now that mass, position-labeled recency, and the sink hypothesis are all ruled out? A k-context sweep — computing the shadow's cache with a controlled amount of real preceding context, from zero up to the full real prompt, and measuring divergence as a function of that amount — was proposed as the next step specifically because it is not something a text prefix can express at all, unlike everything ruled out so far.
- Is the weapons topic's reversal (real content collapsing more than neutral) explained by anything measurable, given that the structure account never had traction there?
- How much of this project's historical "no collapse" results change once systematically re-run with `repetition_penalty` made explicit, beyond the three cells we spot-checked?
- Would layer-restricted splicing (injecting phantom KV into only a subset of layers) localize the sentence-boundary effect to a specific part of the network? This is one of the few remaining manipulations in this space that a text prefix genuinely cannot express, and would need a fluency-degradation control alongside P(EOS) to distinguish "these layers carry the effect" from "splicing partial layers just breaks the model."

## Reproduction

Code lives in `kv_injection/experiment.py`. It consolidates what used to be several separate modules into one file and has grown substantially since the original matrix: it now includes the genuine-prefill control, P(EOS) measurement (spliced and genuine, with and without leading-token drops, at arbitrary jittered cut points), the position-flip manual decoding loop, the cross-pairing matrix, the stability sweep, and the sentence-boundary comb test, alongside the original splice primitive and run matrices. Run `python kv_injection/experiment.py --help`-equivalent by reading the subparser list in `main()` for the full current command set; `test` runs smoke tests with no model load, and `verify` reproduces this post's originally-quoted Qwen examples byte-for-byte against stored results, which is also what caught a real bug introduced during an earlier consolidation pass.

Raw results live in `results/experiment_a_results.json` through `results/experiment_m_boundary_comb.json` (see filenames for which experiment each corresponds to), with running notes in `results/followup_findings.md`, `results/neutral_control_findings.md`, `results/splice_explainer.md`, and a full chronological lab log of this entire investigation, including several dead ends and corrected mistakes not detailed in this post, in `results/session_log.md`.

The primary model was [Qwen2.5-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) in fp16. The generalization check used [TinyLlama/TinyLlama-1.1B-Chat-v1.0](https://huggingface.co/TinyLlama/TinyLlama-1.1B-Chat-v1.0), also in fp16. Library versions were `transformers==5.15.1` and `torch==2.13.0`. Hardware was an Apple M1 Pro with 16GB of unified memory, using the `mps` backend.

If you are trying to reproduce any of this, three details are the most likely to trip you up. The `position_ids` offset for the shadow forward pass: get this wrong and you will probably still see some effect, but it will not mean what you think it means. The `DynamicCache` API in `transformers`, where each layer's keys and values are directly reassignable tensors rather than something you update through a method call. And, learned the hard way in this project: check your model's default `GenerationConfig` before trusting any decode-based measurement of termination, refusal, or early-stopping behavior. If it ships a nonzero `repetition_penalty` and your prompt template repeats its own end-of-sequence token anywhere — which most chat templates do, at every turn boundary — that penalty is working against you before your actual experiment even starts.
